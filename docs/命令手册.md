# 命令手册

所有命令都在项目根目录 `` 下执行。
下面统一用 `python` 代指你的解释器，任意装有 PyYAML 的 Python 3.9+ 环境均可：

```
python
```

先确认环境没问题：

```bash
cd bytedance
python run.py list
```

能看到套件、评分表、能力维度、模型状态四段输出，就说明环境是好的。

## 一、命令总览

| 命令 | 作用 | 会不会花钱 |
|---|---|---|
| `run.py list` | 列出套件 / 评分表 / 维度 / 模型可用状态 | 不花钱 |
| `run.py run` | 执行一次评测 | **会**（调模型） |
| `run.py report` | 由已有结果生成报告 | 不花钱（纯本地） |
| `run.py calibrate` | 用人工标注算裁判一致性 κ | 不花钱 |
| `run.py failures` | 在终端快速看失败样本 | 不花钱 |
| `run.py --version` | 版本号 | — |

辅助脚本：

| 脚本 | 作用 | 会不会花钱 |
|---|---|---|
| `scripts/mock_run.py` | 离线一键演示（全 mock，验证流水线） | 不花钱 |
| `scripts/build_eval_set.py` | 评测集构建流水线（打分 → 去重 → 分层抽样） | 默认不花钱，加 `--llm` 才花 |
| `scripts/from_badcase.py` | 数据飞轮：从失败样本生成候选新题 | 不花钱 |
| `scripts/gen_images.py` | 重新绘制多模态题库的图片资产 | 不花钱 |
| `scripts/audit_isolation.py` | 数据集答案隔离自检（防答案被写进题面）；`--fail-on-leak` 供 CI 用 | 不花钱 |

## 二、六个典型场景

### 场景 1：多个大模型横向对比（最常用）

这是这套框架的主线用途：把几个模型放进同一套评测集，用同一套判定标准打分，横向比出强弱。

**第一步**：在 `configs/models.yaml` 里启用你想比的模型（详见第四节）。

**第二步**：跑评测，带上 `--pairwise` 做两两对比。

```bash
python run.py run --suite all --pairwise
```

**第三步**：看报告。

```bash
python run.py report --run latest --open
```

报告里跟横评直接相关的四块：

| 区块 | 看什么 |
|---|---|
| 模型榜单 | 综合分排名 + **95% 置信区间**。区间重叠的两个模型，排名差异不成立 |
| 能力画像 | 雷达图。谁在哪个维度强、哪个维度弱，一眼看出来 |
| 维度得分矩阵 | 模型 × 维度 的完整热力表，定位到具体某格 |
| 胜率矩阵 | 两两对比胜率。已做双向换位，位置敏感的部分记平局 |

**只比指定的几个模型**（比如临时加进来对比的一个新模型）：

```bash
python run.py run --suite all --suts mock-strong,mock-weak --pairwise
```

`suts` 参数的取值就是 `configs/models.yaml` 里每个模型的 `id`。

### 场景 2：只跑某个能力维度

套件按维度拆成了四种粒度，跑小的更快更省：

```bash
# 只跑通用能力（知识 / 指令 / 推理 / 代码 / 长文本 / 知识图谱 / 真实任务）
python run.py run --suite general

# 只跑 Agent 工具调用
python run.py run --suite agent

# 只跑多智能体协作
python run.py run --suite multi_agent

# 只跑安全与鲁棒
python run.py run --suite safety

# 全量（默认）
python run.py run --suite all
```

### 场景 3：先小规模试跑，确认无误再全量

接好新模型的 key 之后，别直接全量跑 —— 先跑十几题确认链路是通的。

```bash
python run.py run --suite all --limit 12 --no-report
```

`--limit 12` 表示只取前 12 题；`--no-report` 表示只跑不出报告，省一步。

确认没报错之后，再去掉这两个参数全量跑。

### 场景 4：用人工标注校准裁判

**这是让报告里的分数站得住脚的关键一步。** 不做校准，裁判分数只能当参考。

**第一步**：人工按评分表给一批样本打分，写成 JSONL，格式见
`datasets/calibration/gold_helpfulness.jsonl` 的头部注释：

```json
{"sample_id": "kn-001", "sut_id": "mock-strong", "score": 5, "notes": "选项正确"}
```

**第二步**：把标注文件接到评测运行上：

```bash
python run.py run --suite all --calibrate datasets/calibration/gold_helpfulness.jsonl
```

或者对**已有的**评测结果补算（不用重跑，不花钱）：

```bash
python run.py calibrate --run latest --gold datasets/calibration/gold_helpfulness.jsonl
```

报告里「裁判可信度」一节会给出：二次加权 κ、未加权 κ、完全一致率、Spearman ρ、平均绝对误差。

判读标准（Landis & Koch，惯例值）：

| κ | 结论 | 本框架的行为 |
|---|---|---|
| ≥ 0.8 | 几乎完全一致 | 可用于批量打分，仍建议抽检 |
| 0.6 – 0.8 | 强 | 可用，保留人工抽检 |
| < 0.6 | 未达警戒线 | **报告明确标注"只能作参考，不应作为发布门禁依据"** |

> 标注样本少于 10 条时，框架会直接说"样本量不足以给出结论"，不会硬算一个数出来。
> 建议至少 100 条。

### 场景 5：在终端快速看失败样本

比翻 HTML 快得多，排查问题时用这个。

```bash
python run.py failures --run latest --top 8
```

输出每个模型的：综合分、失败归因分布，以及前 N 条失败样本的题面、回答、失败类别。

### 场景 6：只调报告，不重跑模型

评测贵、报告便宜。改了报告模板或者想换个角度分析旧结果时，用这个：

```bash
python run.py report --run latest

# 指定输出路径
python run.py report --run outputs\runs\all_20260914_135415_mock --out 报告.html

# 读某次历史运行
python run.py report --run outputs\runs\<run_id>
```

## 三、参数详解

### `run.py run`

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--suite` | `all` | 套件名。可选 `all` / `general` / `agent` / `multi_agent` / `safety` |
| `--suts` | 空 | 只跑指定模型，逗号分隔。留空表示跑所有 enabled 的模型 |
| `--limit` | `0` | 最多跑几题，0 表示不限。试跑时用 |
| `--pairwise` | 关 | 额外做两两换位对比。想比模型强弱就开 |
| `--calibrate` | 空 | 人工标注文件路径，用于算裁判一致性 |
| `--no-report` | 关 | 只跑评测，不出报告 |
| `--open` | 关 | 出完报告自动用浏览器打开 |

### `run.py report`

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--run` | `latest` | 运行目录。`latest` 表示最近一次 |
| `--calibrate` | 空 | 人工标注文件 |
| `--out` | 运行目录下 `report.html` | 输出路径 |
| `--open` | 关 | 打开报告 |

### `run.py calibrate`

| 参数 | 必填 | 说明 |
|---|---|---|
| `--run` | 否，默认 `latest` | 运行目录 |
| `--gold` | **是** | 人工标注 JSONL |
| `--out` | 否 | 把结果同时写入文件 |

### `run.py failures`

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--run` | `latest` | 运行目录 |
| `--top` | `5` | 每个模型展示几条失败样本 |

## 四、怎么接自己的模型

只用改两个文件，代码一行都不动。

### 4.1 填凭据：`.env`

```bash
cd bytedance
copy .env.example .env
```

然后编辑 `.env`：

```dotenv
ARK_API_KEY=你的火山方舟key
DEEPSEEK_API_KEY=你的deepseek key
DASHSCOPE_API_KEY=你的通义key
```

`.env` 已在 `.gitignore` 里，不会被提交。

### 4.2 启用模型：`configs/models.yaml`

```yaml
suts:
  - id: doubao-seed            # 这个 id 就是 --suts 参数用的值
    provider: ark              # 引用 providers 里定义的服务商
    model: "你的接入点ID"       # ← 填这里
    temperature: 0.0
    enabled: true              # ← 改成 true
```

改完执行 `run.py list` 验证。它会逐行标出每个模型是 `✓ 可用` 还是 `· 跳过`，
跳过原因会写清楚是缺 key、没填模型名，还是被 `enabled: false` 关掉了。

### 4.3 支持的 provider

已内置：火山方舟、DeepSeek、Moonshot、阿里通义、智谱 GLM、OpenAI。

加一个新的只要在 `providers` 下加一条（都是 OpenAI 兼容协议）：

```yaml
providers:
  my_provider:
    label: 某服务商
    base_url: https://api.example.com/v1
    api_key_env: MY_API_KEY
```

## 五、输出文件说明

每次运行会在 `outputs/runs/<run_id>/` 下产生：

| 文件 | 内容 |
|---|---|
| `report.html` | 单文件 HTML 报告，双击就能看，无外部依赖 |
| `turns.jsonl` | 逐条记录：题面 + 原始回答 + 全部判定依据（可追溯性的核心） |
| `summary.json` | 运行元信息与汇总统计 |
| `pairwise.json` | 两两对比的原始记录（开了 `--pairwise` 才有） |

`run_id` 长得像 `all_20260914_135415_mock`：套件名 + 时间戳 + 是否含 mock。

**目录体积**：一次全量运行约 0.6 MB。`outputs/` 整个目录可以随时删，不会影响任何
已交付的评测结论 —— 它是产物不是数据源。

缓存目录 `outputs/.cache/` 存的是 LLM 响应，纯文本 JSON，会随重复调用增长。
重跑同样的配置时它能让第二次几乎不花钱。

## 六、配置文件速查

| 想改什么 | 改哪里 |
|---|---|
| 加减模型、填 key | `configs/models.yaml` |
| 并发数、超时、重试、缓存开关 | `configs/models.yaml` 的 `runtime` 段 |
| 某次评测跑哪些题、用哪个裁判、跑几遍 | `configs/suites/*.yaml` |
| 评分标准（criterion / 步骤 / 锚点） | `configs/rubrics/*.yaml` |
| 评测题 | `datasets/**/*.jsonl` |
| 评测集字段规范 | `datasets/schema.md` |

**加一条裁判指标不需要写 Python** —— 只要在 `configs/rubrics/` 下加一个 YAML，
框架会自动按 G-Eval 范式构建 prompt、解析输出、并入统计。

## 七、常见问题

**Q：跑出来全是 mock，怎么看真实结果？**
A：说明你没启用真实模型。去 `configs/models.yaml` 把对应模型的 `enabled` 改成 `true`
并填上 `model`，再跑 `run.py list` 确认状态变成 `✓ 可用`。
报告页首如果有红色警示条，就说明这次运行里含 mock，不能当真实结论。

**Q：报告里说"维度少于 3 个，无法绘制雷达图"？**
A：正常。雷达图需要至少 3 个维度。用 `--limit` 限制题量时，很可能只覆盖了一两个维度。

**Q：报告里「裁判可信度」是空的？**
A：因为没提供人工标注。这是刻意设计 —— 宁可留空，也不用别的指标顶替。
跑 `run.py calibrate --gold <标注文件>` 就有了。

**Q：`--pairwise` 会让调用量翻倍吗？**
A：会。每个模型配对要判两次（双向换位）。N 个模型、M 道题，
调用量约为 M × C(N,2) × 2。模型多的时候按需开。

**Q：换题之后原来的 κ 还有效吗？**
A：无效。换评分表、换裁判、换被测模型、或者过了 60–90 天，都必须重新校准。
服务商会在背后悄悄更新模型，这是最容易被忽略的一条。
