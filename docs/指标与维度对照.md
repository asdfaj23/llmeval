# 指标与维度对照

## 一、为什么需要这张表

评测最容易含糊的三个问题：

1. **一个维度到底看哪个指标？** 「知识维度 4.82 分」——这个分是怎么来的，规则判的还是裁判打的？
2. **同类能力，别人怎么测的？** 没有 benchmark 对照，结论就只是自说自话。
3. **哪些指标是硬判定、哪些是主观分？** 混在一起看，会把「格式合规」和「内容质量」当成同一件事。

所以每个维度都明确三件事：**对标哪个公开 benchmark、产出哪些指标、每个指标由哪一层判定。**

判定层级只有三种（`schema.TIERS`）：`deterministic`（规则，零成本零偏差）、
`llm_judge`（裁判，需先过 κ 校准）、`human`（人工，只做校准基准）。

## 三、指标口径速查

### 3.1 规则层指标（确定性，零 API 成本）

| 指标 | 定义 | 通过线 |
|---|---|---|
| `instruction_rules` | 8 类显式约束的满足情况：必须包含 / 禁止出现 / 字数上下限 / 行数 / 正则全匹配 / JSON 结构 / 语言 / 无开场白 | score ≥ 4（一处硬违规即 2 分） |
| `answer_match` | 选择题比对选项字母；数值题比相对误差；开放题算字面 F1（仅作参考信号） | score ≥ 4 |
| `coding_exec` | 子进程真实执行测试用例 | **全过**才算 pass@1 |
| `agent_tools` | 实际工具序列 vs 期望序列：precision / recall / F1，另计冗余步数与漏调工具 | score ≥ 3.5 |
| `agent_safety` | 是否调用了 `forbidden_tools` 里的禁用工具 | 未调用 = 通过 |
| `containment` | 答案隔离自检 + canary 泄漏扫描 + 轨迹审计 | 无越界 = 通过；**不进质量分，只披露** |
| `pass@k` / `pass^k` | 至少一次成功（能力上限） / k 次全成功（可靠性） | 无阈值，看两者差距 |

### 3.2 裁判层指标（需过 κ ≥ 0.6 校准）

| 指标 | 评分表 | 通过线 |
|---|---|---|
| `judge:helpfulness` | 有用性：correctness 0.40 / completeness 0.25 / relevance 0.20 / clarity 0.15 | score ≥ 4 |
| `judge:instruction_following` | 指令遵循（按硬 / 软约束数映射档位） | score ≥ 4 |
| `judge:faithfulness` | 事实忠实（按 unsupported 数映射档位） | score ≥ 4 |
| `judge:agent_trajectory` | 智能体轨迹质量 | score ≥ 4 |
| `judge:collaboration` | 协作过程质量 | score ≥ 4 |
| `judge:knowledge_graph` | 三元组与路径质量 | score ≥ 4 |

### 3.3 偏差与可信度指标（都不是「模型得分」）

| 指标 | 定义 | 判据 |
|---|---|---|
| Cohen's κ / 二次加权 κ | 裁判与人工标注的一致度（扣掉瞎蒙） | **≥ 0.6** 才可作为依据 |
| 位置偏差 | 换位重测后结论一致的比例 | ≥ 0.9 很小 |
| 冗长偏差 | 「更长的回答获胜」的比例 | ≤ 0.55 无 |
| 同族偏袒 | 裁判与被测模型是否同家族 | 同族即告警 |
| 评审团一致性 | 多个裁判之间的 κ | ≥ 0.8 提示同质 |
| McNemar / bootstrap CI | 模型差距是否显著 | p < 0.05 且区间不跨 0 |

## 四、指标的口径原则（三条，别踩）

1. **规则分和裁判分不混着平均。** 一旦平均，「格式合规」这种确定性结论会稀释掉质量信号。
   代码里的做法是：有裁判分就用裁判分，没有才退回确定性判定的均值（`analysis.final_score`）。
2. **参差不决定通过率。** 像开放题的字面 F1 这种参考性指标，`decisive=False`，
   它不参与「这条记录算不算通过」，否则「换个说法表达同一个意思」会被误判为失败。
3. **环境问题不进能力分。** 隔离审计的越界记录同样 `decisive=False`：
   它是「这轮结果能不能用」，不是「模型好不好」。

## 五、加维度 / 加指标时的自检

- [ ] 新维度在 `schema.DIMENSIONS` 里补齐四个字段：`name` / `seed_anchor` / `benchmark` / `metrics`。
- [ ] 新指标要明确 `tier`（规则 / 裁判 / 人工），并想清楚它是否 `decisive`。
- [ ] 如果新指标要交给裁判，先补一条金标集，跑通 κ ≥ 0.6 再加入。
- [ ] 更新本文件的第二节表格；报告末尾的溯源卡片会自动跟随 `DIMENSIONS` 更新。
