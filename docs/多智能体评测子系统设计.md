# 多智能体协作评测子系统 —— 升级设计方案

> 定位:把 `multi_agent` 从"13 个维度之一"升级为独立子系统,补齐过程级指标、失败归因、可重放沙箱;顺带完成 P1 轨迹级 Agent 评测深化。
> 约束:不引入重型分布式框架;单人维护;CPU + 已有 API key;全部改动保持可复现、可归因。

---

## 一、现状诊断(5 个具体缺口,均有代码依据)

### 缺口 1:协作形态是"固定剧本",没有 Router,修订轮无法重新调用工具

`multi_agent_sut.py` 的流程写死为 planner → executor → reviewer 循环(最多 2 轮)→ final:

- **无 Router**:四个角色里只有三个。Router(按子任务性质路由给不同能力/模型)完全没有;也没有"单模型多角色 vs 多模型异构"的开关——现在所有角色必然是同一个 SUT。
- **工具只在第 1 轮真执行**(`multi_agent_sut.py:129-131` 注释明说"工具只在第一轮真的执行一次")。这意味着**子任务失败恢复根本没有观测通道**:第 1 轮工具失败了,修订轮只能"改说法",不能重新调工具。凡是需要"失败→重试→成功"的题,当前架构天然测不出来。

### 缺口 2:过程留痕被截断,现场不可重放

- 协作消息 `content` 落盘时截断到 400 字(`multi_agent_sut.py:288` `make_snippet(content, 400)`)。规划文本超过 400 字的部分永久丢失。
- **planner 的 `args` 没有单独留痕**(`multi_agent_sut.py:100-108`):只存了 `steps` 和 `plan`(工具名列表),参数表丢了。
- `run_tool_plan`(`tools.py:148-157`)把 planner 给的**同一份 args 复制到每一步**——轨迹里没有"这一步用了什么参数"的概念。
- 后果:判分够用,**重放不够**。无法回答"如果 executor 换一个模型、看到同样的规划,还会漏掉单位问题吗"这类反事实问题——而这正是多智能体评测最有价值的部分。

### 缺口 3:只有 3 个结构分,没有过程成本指标,更没有失败归因

`metrics/collaboration.py` 现有 roles / review / revision 三个确定性指标,覆盖了"制衡机制是否成立",但:

- **成本维度为零**:平均轮次、token/调用开销(按角色)、无效轮次占比(被否决后修订了但内容与上轮几乎相同)、协作中断率(planner 输出解析失败、轮次预算耗尽)——全都没有。
- **失败归因为零**:失败只有 `Response.error` 一个字符串。规划错、工具错、角色间信息丢失、冲突没解决、提前终止——五种完全不同的病,现在混在一起,报告里看不到分布。

### 缺口 4(P1 核心):单 Agent 轨迹是"开环计划执行",测不到长程能力

`run_tool_plan` 把 planner 一次性给出的计划顺序跑完,模型**看不到任何一步的执行结果**。所以:

- "5 步以上长程任务 + 中途失败后重规划"这种最能区分 agent 好坏的题,当前架构**测不到**——失败发生在第 3 步,第 4、5 步照样按原计划跑。
- 参数正确率算不了:没有逐步参数,就没有"这一步参数对不对"。

### 缺口 5:协作质量的语义层判定缺失,"关键词埋点"可被绕过

- `expected_reviewer_flag: ["单位"]` 是子串匹配(`collaboration.py:104`)——reviewer 只要提到"单位"二字就算抓到,哪怕说的和埋的坑毫无关系。
- 任务分解合理性(拆得对不对、粒度合不合适)无判定。**这一项没有 gold,程序化不可行**,需要降级方案(见 §二.4)。

## 二、模块设计

### 2.1 架构:新增 `src/llmeval/collab/` 子系统

```
src/llmeval/collab/
├── __init__.py        # CollabRuntime 注册进 sut/__init__.py 的 _KIND_BY_TASK(架构约定)
├── roles.py           # 角色定义:角色 = 系统提示 + 输出 schema + 工具权限
├── runtime.py         # 协作运行时:消息总线、轮次调度、Router、预算控制
├── replay.py          # 可重放沙箱:从 runs/ 落盘记录重建现场、反事实重放
├── attribution.py     # 失败归因五分类
└── metrics.py         # 过程级指标(承接并扩展 metrics/collaboration.py)
```

**运行时核心思想**:协作 = 事件循环。每个角色是一个"系统提示 + 输出 JSON schema"的函数,Router 是第四个角色。预算控制(轮次/token/时间)在 runtime 层统一强制,而不是散在各 SUT 里。

**角色机制(覆盖 P0 要求)**:

| 机制 | 实现方式 | 成本 |
|---|---|---|
| Planner/Executor/Critic/Router 分工 | `roles.py` 中每个角色一个 `RoleSpec(name, system, output_schema, tools_allowed)` | 零额外成本 |
| 单模型多角色 | 默认:全部角色用当前 SUT 的 client | 现状持平 |
| 多模型异构协作 | 题/套件级 `meta.role_map: {"reviewer": "doubao-seed-2-0"}`,runtime 按角色路由到不同 client(复用已有 `client.py`) | 每题 5–8 次调用,只在抽样子集开启 |

**调度循环(runtime.py 伪代码)**:

```
budget = Budget(max_rounds=8, max_tokens=N, deadline=T)
state = Step0: Router(任务) → 决定本轮该谁发言、为什么
loop:
    role_out = call(role_map[state.next_role], messages, budget)   # 结构化 JSON
    if role 是 executor 且声明需要工具: 真执行(每轮都可调,不再限第 1 轮)
    messages.append(结构化事件)
    if role_out.action == "deliver" or budget 耗尽: break
```

### 2.2 数据结构(零 schema 破坏性变更)

**设计原则:结构化信息全部塞进已有的 `trace`(工具轨迹)与 `messages`(协作消息)两个通道,不改 `schema.Response` 字段** —— 旧 runs 仍可读,不触发"过程记录新增字段必须同步 pipeline.load_run"的兼容成本。只在确需新通道时加一个 `Response.events`(同步改 `pipeline.load_run`,一次性)。

### 2.3 指标定义表

| 指标 | 定义 | 计算 | 判定归属 |
|---|---|---|---|
| task_completion | 任务完成率 | 现有结果层判定(确定性比对/裁判),不变 | **decisive**,决定 pass |
| avg_rounds | 平均轮次 | Σ len(messages)/n,分角色分桶 | 诊断,不计分 |
| token_overhead | 协作开销 | Σ usage(按角色分解);对比"同题单 agent"的 usage 算协作溢价 | 诊断,不计分 |
| invalid_round_ratio | 无效轮次占比 | (被否决后修订但与上轮编辑距离相似度>0.9、或未引用任何 issue 的轮次)/总修订轮 | 计分 1–5,decisive=False |
| interruption_rate | 协作中断率 | (planner 解析失败 + 预算耗尽仍未 deliver)/总运行数 | 布尔/比例,decisive |
| reviewer_zeal | 审查者勤勉度 | 二维:该否题中否决率 × 干净题中误伤率(现有 evaluate_review 升级) | 计分,decisive |
| convergence | 一致收敛 | 末轮 verdict=approve 且修订轮数:0–1 轮=5 分,2 轮=4 分,耗尽预算仍 reject=1 分 | 计分,decisive=False |
| subtask_recovery | 子任务失败恢复 | 故障注入题:失败步之后出现同工具重试且成功,或显式说明失败并降级交付 | 计分,**decisive** |
| decomposition_validity | 任务分解合理性 | 降级方案见 §2.4 | 见 §2.4 |
| (P1) call_success_rate | 调用成功率 | Σ step.ok / Σ steps | 计分,decisive=False |
| (P1) param_validity | 参数正确率 | 每步必需参数齐备且类型合法(复用 tools.py 的 per-tool 校验)÷ 总步数 | 计分,decisive=False |
| (P1) retry_recovery | 重试恢复率 | 失败步后 2 步内同工具成功重试的次数 / 失败步总数 | 计分,decisive |
| (P1) redundant_call_rate | 冗余调用率 | 超出 expected 次数的调用 / 总调用(现有 redundant 升级为比率) | 计分,decisive=False |

**失败归因(五分类,`attribution.py`,规则优先、裁判兜底)**:

| 归因 | 触发规则(全部可程序化) |
|---|---|
| planning_error | plan 含非法工具名 / 缺题目必需工具 / args 缺必需键 / steps 数与 plan 数脱节 |
| tool_error | trace 中存在 ok=False 的步,且最终答案未通过结果层判定 |
| info_loss | reviewer 提出的 issue 在 final 文本中零字符重叠,或修订轮内容与 issue 无关 |
| conflict_unresolved | 题目埋了数据冲突(expected_conflict)而 final 仍直接给出单一结论 |
| premature_termination | 预算耗尽/异常中断,或 deliver 时末轮 verdict 仍为 reject |

归因是**诊断输出不是分数**:每条失败记录打标签,报告层出"失败归因直方图"(五类各占多少),这才是修系统的依据。

### 2.4 不可行指标与降级方案(按约束要求明确列出)

| 想测的 | 为什么不可行 | 降级方案 |
|---|---|---|
| 任务分解合理性(语义级) | "拆得好不好"没有唯一答案,程序判不了;全交裁判则 24 题×每题多一次调用且主观 | 双层:结构校验(合法工具/必需工具覆盖/steps-plan 一致性)走确定性;语义质量在裁判 rubric 加 1 条,只对 multi_agent 子集生效 |
| 跨模型 token 开销归一比较 | 不同模型分词器和定价不同,归一后数字会误导 | 分角色分开报告原始 token 与费用,不做跨模型归一 |
| 一致性收敛的强结论 | 单模型多角色时,三个角色共享同一模型的自偏好,收敛快可能只是"自己认同自己" | 报告显式披露"同族收敛,仅供参考";强结论只在异构子集上算 |
| 多模型异构协作全量跑 | 每题 5–8 次调用,290 题全量成本约 3 倍 | 只在 multi_agent 24 题中抽 8 题(分层:难度×埋点类型)开异构模式 |
| 中断率/无效轮占比的稳定估计 | 12 题样本太小,比例波动大 | 题库扩到 24 题后再报比例;12 题阶段只报计数 |

### 2.5 可重放沙箱(replay.py)

工具集已是纯函数(不写盘、不联网、确定性输出),所以重放天然安全且可复现:

- **现场重建**:`runs/<run_id>/turns.jsonl` → `Response.messages/trace` → 还原每一轮的完整输入(前提:缺口 2 修复,不再截断)。
- **单步重放**:固定前缀消息 + 只对某个角色重新调 API,其余角色从记录回放。
- **反事实重放**(杀手锏,面试最有讲头):"同一道题,把 reviewer 换成豆包,还会放过单位错误吗?"——回答这个问题只需要一次角色级重放,不用重跑整个协作。
- **确定性保证**:同 sample_id + 同角色序列 + 同模型 → 可复算;`run_id + attempt_index + step` 三元组定位任何一步。

### 3.1 轨迹记录(修复缺口 2 + P1 逐步留痕)

```python
# src/llmeval/collab/trace_recorder.py
# -*- coding: utf-8 -*-
"""结构化轨迹记录:协作消息与工具步进,全部不截断、逐步独立留痕。"""

from __future__ import annotations
from dataclasses import dataclass, field, asdict
from typing import Any


@dataclass
class ToolStep:
    """一次工具调用。args 是本步独立参数,不再是共享参数表。"""
    step: int
    tool: str
    args: dict[str, Any]
    result: str
    ok: bool
    error: str | None = None
    retry_of: int | None = None          # 指向被重试的失败步
    latency_s: float = 0.0

    def to_dict(self) -> dict[str, Any]:
        return asdict(self)


@dataclass
class CollabMessage:
    """一条协作消息:全文 + 结构化输出 + 路由决策 + 逐角色开销。"""
    turn: int
    role: str                            # planner / executor / reviewer / router
    content: str                         # 全文,不截断(展示摘要交给 report 层)
    structured: dict[str, Any] = field(default_factory=dict)
    router_decision: dict[str, Any] | None = None
    latency_s: float = 0.0
    usage: dict[str, int] = field(default_factory=dict)

    def to_msg(self) -> dict[str, Any]:  # 落盘格式,兼容 messages 通道
        d = {"turn": self.turn, "role": self.role, "content": self.content,
             "length": len(self.content)}
        if self.structured:
            d["structured"] = self.structured
        if self.router_decision:
            d["router"] = self.router_decision
        if self.usage:
            d["usage"] = self.usage
            d["latency_s"] = round(self.latency_s, 3)
        return d


def record_tool_steps(raw_steps: list[dict[str, Any]]) -> list[dict[str, Any]]:
    """把 runtime 产生的 ToolStep 序列转为可落盘轨迹(带 retry_of 链)。"""
    return [ToolStep(**s).to_dict() if isinstance(s, dict) and "ok" in s else s
            for s in raw_steps]
```

### 3.2 指标计算(过程级,全部确定性 tier)

```python
# src/llmeval/collab/metrics.py
# -*- coding: utf-8 -*-
"""协作过程级指标:成本、收敛、无效轮、故障恢复。全部基于 messages/trace,零裁判。"""

from __future__ import annotations
from difflib import SequenceMatcher
from ..schema import Response, Sample, Verdict


def _reviews(msgs):  return [m for m in msgs if m.get("role") == "reviewer"]
def _execs(msgs):    return [m for m in msgs if m.get("role") == "executor"]


def evaluate_convergence(sample: Sample, response: Response) -> Verdict | None:
    """一致收敛:末轮 approve 且修订代价可控。同族自偏好在报告层披露。"""
    if sample.task_type != "multi_agent":
        return None
    msgs = response.messages or []
    revs = _reviews(msgs)
    if not revs:
        return None
    verdicts = [str(m.get("structured", {}).get("verdict") or m.get("verdict") or "")
                for m in revs]
    n_rev_needed = sum(1 for v in verdicts[:-1] if v == "reject")   # 进入收敛前的否决数
    if verdicts[-1] != "approve":
        score, note = 1.0, "预算内未收敛:末轮仍为否决"
    elif n_rev_needed <= 1:
        score, note = 5.0, "至多一轮修订即收敛"
    elif n_rev_needed == 2:
        score, note = 4.0, "两轮修订后收敛"
    else:
        score, note = 2.0, "多轮反复,收敛质量差"
    return Verdict(sample.id, response.sut_id, "collab_convergence", "deterministic",
                   score=score, passed=score >= 4,
                   detail={"verdicts": verdicts, "revision_rounds": n_rev_needed, "note": note},
                   attempt_index=response.attempt_index)


def evaluate_invalid_rounds(sample: Sample, response: Response) -> Verdict | None:
    """无效轮次占比:被否决后的修订是否真的在改(与上轮相似、或不回应意见 => 无效)。"""
    if sample.task_type != "multi_agent":
        return None
    msgs = response.messages or []
    rejected = any(_is_reject(m) for m in _reviews(msgs))
    if not rejected:
        return None
    execs = _execs(msgs)
    if len(execs) < 2:
        return Verdict(sample.id, response.sut_id, "collab_invalid_rounds", "deterministic",
                       score=1.0, passed=False,
                       detail={"reason": "有否决但无修订轮,协作断链"},
                       attempt_index=response.attempt_index)
    prev = execs[0].get("content") or ""
    issues = [i for m in _reviews(msgs) for i in (m.get("structured", {}).get("issues")
             or m.get("issues") or [])]
    invalid = 0
    for cur in execs[1:]:
        text = cur.get("content") or ""
        similar = SequenceMatcher(None, prev, text).ratio() > 0.9
        addresses = any(str(i)[:12] in text for i in issues)   # 修订是否回应了意见
        if similar or (issues and not addresses):
            invalid += 1
        prev = text
    ratio = invalid / max(1, len(execs) - 1)
    score = round(5.0 - min(4.0, ratio * 5.0), 2)
    return Verdict(sample.id, response.sut_id, "collab_invalid_rounds", "deterministic",
                   score=max(1.0, score), passed=score >= 4,
                   detail={"revision_rounds": len(execs) - 1, "invalid_rounds": invalid,
                           "invalid_ratio": round(ratio, 4)},
                   attempt_index=response.attempt_index)


def evaluate_recovery(sample: Sample, response: Response) -> Verdict | None:
    """子任务失败恢复:仅对故障注入题生效(planted_failure)。"""
    if not (sample.meta or {}).get("planted_failure"):
        return None
    failed = [s for s in (response.trace or []) if not s.get("ok")]
    if not failed:
        return Verdict(sample.id, response.sut_id, "collab_recovery", "deterministic",
                       score=5.0, passed=True,
                       detail={"note": "预期故障未复现(环境侧需检查)",
                               "planted": sample.meta["planted_failure"]},
                       attempt_index=response.attempt_index)
    steps = {s.get("step"): s for s in response.trace or []}
    recovered = 0
    for f in failed:
        for later in (response.trace or []):
            fs, ls = f.get("step"), later.get("step")
            if ls and fs and ls > fs and ls <= fs + 2 and later.get("tool") == f.get("tool") \
                    and later.get("ok") and later.get("retry_of") == fs:
                recovered += 1
                break
    # 兜底:没有重试但 final 明确披露失败并降级交付,算部分恢复
    final_ok = response.ok and any(
        k in (response.text or "") for k in ("未能获取", "缺失", "无法确认"))
    score = 5.0 if recovered == len(failed) else (3.5 if final_ok else 1.0)
    return Verdict(sample.id, response.sut_id, "collab_recovery", "deterministic",
                   score=score, passed=score >= 3.5,
                   detail={"failed_steps": [f.get("step") for f in failed],
                           "recovered": recovered, "degraded_delivery": final_ok},
                   attempt_index=response.attempt_index)


def _is_reject(m: dict) -> bool:
    s = m.get("structured", {})
    return str(s.get("verdict") or m.get("verdict") or "").strip().lower() == "reject"


def collect_process_metrics(sample: Sample, response: Response) -> list[Verdict]:
    if not response.ok:
        return []
    out = []
    for fn in (evaluate_convergence, evaluate_invalid_rounds, evaluate_recovery):
        v = fn(sample, response)
        if v is not None:
            out.append(v)
    return out
```

### 3.3 失败归因(五分类,规则可解释)

```python
# src/llmeval/collab/attribution.py
# -*- coding: utf-8 -*-
"""失败归因:只对"结果层失败"的记录打标签,输出诊断直方图,不计分。"""

from __future__ import annotations
from typing import Any

TAXONOMY = ("planning_error", "tool_error", "info_loss",
            "conflict_unresolved", "premature_termination")

VALID_TOOLS = {"search_corpus", "calculator", "get_field", "finish"}


def attribute_failure(sample: Sample, response: Response) -> list[dict[str, Any]]:
    """返回按置信度排序的归因标签列表(可多标签)。全部为规则判定,可复现。"""
    msgs = response.messages or []
    planner = next((m for m in msgs if m.get("role") == "planner"), None)
    structured = planner.get("structured", {}) if planner else {}
    plan = structured.get("plan") or planner.get("plan") or [] if planner else []
    args = structured.get("args") or {}
    tags: list[dict[str, Any]] = []

    # 1. planning_error:计划本身就不成立
    bad_tools = [t for t in plan if str(t) not in VALID_TOOLS]
    if bad_tools or (not plan and planner is not None):
        tags.append({"tag": "planning_error", "evidence": f"非法/空工具计划: {bad_tools}"})

    # 2. tool_error:轨迹里有失败步
    failed_steps = [s for s in (response.trace or []) if not s.get("ok")]
    if failed_steps:
        tags.append({"tag": "tool_error",
                     "evidence": [f"step {s.get('step')} {s.get('tool')}: {s.get('error')}"
                                  for s in failed_steps]})

    # 3. info_loss:reviewer 指出的问题,final 完全没接住
    issues = [i for m in msgs if m.get("role") == "reviewer"
              for i in (m.get("structured", {}).get("issues") or m.get("issues") or [])]
    final_text = response.text or ""
    if issues and not any(str(i)[:10] in final_text for i in issues):
        tags.append({"tag": "info_loss",
                     "evidence": f"{len(issues)} 条审查意见未进入最终答案"})

    # 4. conflict_unresolved:题目埋了矛盾,final 仍给单一结论
    if (sample.meta or {}).get("expected_conflict") and any(
            k in final_text for k in ("为", "是", "等于")) and "矛盾" not in final_text \
            and "核实" not in final_text:
        tags.append({"tag": "conflict_unresolved", "evidence": "材料自相矛盾但直接给单一结论"})

    # 5. premature_termination:预算耗尽或带病交付
    if not response.ok or any(
            _is_reject(m) for m in msgs if m.get("role") == "reviewer") and not msgs[-1:] == []:
        last_review = [m for m in msgs if m.get("role") == "reviewer"]
        if last_review and str(last_review[-1].get("structured", {})
                .get("verdict", "")).lower() == "reject":
            tags.append({"tag": "premature_termination",
                         "evidence": "末轮审查仍为否决即交付"})

    return tags


def _is_reject(m: dict) -> bool:
    s = m.get("structured", {})
    return str(s.get("verdict") or m.get("verdict") or "").strip().lower() == "reject"
```

### 3.4 P1:单 Agent 从"开环计划"升级为"逐步闭环"(改动点)

`agent_sut.py` 的执行段替换为 ReAct 式循环(每步:模型看到上一步结果 → 决定下一步):

```python
# agent_sut.py 执行循环(骨架)
history = [planner_first_step]
for step_no in range(1, self.max_steps + 1):
    r = self.client.chat(history + [render(step_no, trace)])       # 模型看到全部历史
    decision = extract_json(r.text) or {}
    tool, args = decision.get("tool"), decision.get("args") or {}
    result, ok = dispatch(tool, args, sample)                      # 独立参数逐步执行
    trace.append({"step": step_no, "tool": tool, "args": args,
                  "result": snippet(result), "ok": ok,
                  "retry_of": last_failed_step if is_retry else None})
    if tool == "finish" or (not ok and not decision.get("retry")):
        break
```

配套:长程题 `meta.long_horizon: true` + `expected_steps_min: 5` + `planted_failure`(第 k 步注入失败),失败判定 = "结果层通过 且 失败步有恢复或显式降级"。
